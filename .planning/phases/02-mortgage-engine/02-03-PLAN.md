    - total_interest_paid: Decimal (sum of interest for months in this year)
    - total_payments: Decimal (sum of payments for months in this year)
    - year_end_balance: Decimal (remaining balance after last month of this year)
    - equity: Decimal (purchase_price - year_end_balance)

    ```python
    def generate_annual_summaries(
        schedule: list[AmortizationEntry],

    ) -> list[AnnualSummary]:
        ...
    ```

    Group monthly entries by calendar year (using the date field). For partial first/last years, include whatever months fall in that calendar year. Down payment contributes to initial equity but is NOT part of the annual summary rows (it is reflected in the starting balance being lower than purchase price).

    **Scenario comparison (per CONTEXT.md locked decision):**
    Side-by-side summary showing key metrics per scenario:
    - scenario_index: int
    - renewal_rates: list[Decimal] (the rates used for each renewal term)
    - total_interest: Decimal
    - total_payments: Decimal
    - final_balance: Decimal
    - months_to_payoff: int
    - total_equity: Decimal (purchase_price - final_balance, should be purchase_price if fully paid off)

    ```python

        scenario_index: int

        total_equity: Decimal

    def compare_scenarios(
        scenarios: list[ScenarioResult],

    ) -> list[ScenarioComparison]:
        ...
    ```

    **Test cases:**
    - Annual summary for a 2-year schedule (24 months): produces 2 AnnualSummary entries
    - Annual summary respects calendar year boundaries (mortgage starting mid-year produces partial first year)
    - Year-end balance matches last month's balance in that year
    - Equity = purchase_price - year_end_balance for each year
    - Sum of all annual totals matches ScenarioResult totals
    - Scenario comparison with 2 scenarios: different total interest values
    - Scenario comparison with 3 scenarios: ordered by scenario_index
    - Full 30-year scenario: 30 annual summaries (or fewer if early payoff / partial last year)
