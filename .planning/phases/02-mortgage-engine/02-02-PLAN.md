<feature>
  <name>Multi-Term Renewal and Scenario Comparison</name>
  <files>maple_return/mortgage.py, tests/test_mortgage_scenarios.py</files>
  <behavior>
    **Term renewal mechanics:**
    - All terms are exactly 5 years (60 months) -- locked decision
    - Initial term (Term 1): uses user-specified payment amount and rate
    - At each 5-year boundary:
      1. Take remaining balance from end of previous term
      2. Calculate remaining amortization months (total - months elapsed)
      3. Apply new renewal rate
      4. Recalculate payment using calculate_standard_payment(remaining_balance, new_monthly_rate, remaining_months)
      5. Generate next term's schedule using calculate_amortization()
    - Continue until balance = 0 or amortization period exhausted

    **Input data structures:**

    ```python
    @dataclass
    class TermDefinition:
        rate: Decimal          # Nominal annual rate for this term
        rate_type: str         # "variable" or "fixed" (metadata, does not affect calculation)

    @dataclass
    class MortgageInput:
        purchase_price: Decimal
        down_payment: Decimal
        annual_rate: Decimal           # Initial term rate
        monthly_payment: Decimal       # Initial term payment (user-specified)
        amortization_years: int        # Total amortization (e.g., 30)
        start_date: date               # First payment date
        rate_type: str                 # Initial term: "variable" or "fixed"
        renewal_scenarios: list[list[TermDefinition]]  # 1-3 lists of renewal terms
    ```

    Each scenario in `renewal_scenarios` is a list of TermDefinition objects for terms 2, 3, 4, etc. If the list is shorter than the remaining terms needed, the last rate repeats for all subsequent terms.

    **Output:**

    ```python
    @dataclass
    class TermSummary:
        term_number: int
        rate: Decimal
        rate_type: str
        monthly_payment: Decimal
        start_balance: Decimal
        end_balance: Decimal
        total_principal: Decimal
        total_interest: Decimal
        months: int

    @dataclass
    class ScenarioResult:
        scenario_index: int               # 0-based
        schedule: list[AmortizationEntry]  # Full monthly schedule
        terms: list[TermSummary]           # Per-term summary
        total_interest: Decimal            # Grand total interest paid
        total_payments: Decimal            # Grand total of all payments
        final_balance: Decimal             # Balance at end (should be 0)
        months_to_payoff: int              # Total months

    def calculate_multi_term(input: MortgageInput) -> list[ScenarioResult]:
        ...
    ```

    **Test cases:**
    - Single term only (no renewals, 5-year term within 30-year amortization)
    - Two terms with same rate (should produce same schedule as single continuous term)
    - Two terms with different rate (payment changes at renewal)
    - Three renewal scenarios at different rates: verify each scenario has different total interest
    - Scenario with rate that causes early payoff within a term
    - Scenario where renewal_scenarios list is shorter than needed (last rate repeats)
    - Full 30-year, 6-term mortgage with varying rates
    - Verify term boundaries: month 60 ends term 1, month 61 starts term 2
    - Verify payment recalculation: at renewal, payment = standard_payment(remaining_balance, new_rate, remaining_months)
  </behavior>
  <implementation>
    Add to `maple_return/mortgage.py`:
    1. `TermDefinition` dataclass
    2. `MortgageInput` dataclass
    3. `TermSummary` dataclass
    4. `ScenarioResult` dataclass
    5. `calculate_multi_term(input: MortgageInput) -> list[ScenarioResult]` function:
       - For each scenario (including a "base" scenario using initial rate for all terms if no renewals):
         - Term 1: call calculate_amortization with user's payment amount, truncate at 60 months
         - For each subsequent term: get remaining balance, remaining months, apply scenario's rate, recalculate payment, call calculate_amortization, truncate at 60 months (or remaining amortization)
         - Concatenate all term schedules into one full schedule
         - Compute TermSummary for each term
         - Compute totals for ScenarioResult

    Handle edge cases:
    - If balance reaches 0 before term ends, stop (no more terms needed)
    - If renewal_scenarios entry has fewer TermDefinitions than remaining terms, repeat the last TermDefinition's rate
    - The rate_type field on TermDefinition is metadata only (variable vs fixed does not change the math, since variable uses a single effective average rate per locked decision)
  </implementation>
</feature>
