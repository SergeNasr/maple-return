  <behavior>
    All functions operate on Decimal types for monetary precision. The metrics module provides pure calculation functions — no side effects, no I/O.

    **1. IRR (Internal Rate of Return)**
    - Signature: `calculate_irr(down_payment: Decimal, monthly_cashflows: list[MonthlyCashFlow], current_property_value: Decimal) -> Decimal | None`
    - Down payment is the initial outflow (negative), monthly net_cashflow values are periodic flows, current_property_value is terminal inflow added to the last period
    - Returns annualized IRR as a decimal (e.g., 0.08 for 8%), or None if IRR cannot be computed (no sign change in cash flows)
    - Use Newton's method or bisection to solve for monthly rate, then annualize: `(1 + monthly_rate)^12 - 1`
    - Do NOT use numpy/scipy — implement IRR solver using pure Python with Decimal. Use float internally for the iterative solver, then convert result back to Decimal
    - Edge cases: all negative flows → None, zero down payment → handle gracefully

    Cases:
    - $100k down payment, 60 months of $500/month positive cash flow, $500k terminal value → IRR ≈ 30-40% (verify range, exact value depends on compounding)
    - $100k down payment, 12 months of -$200/month negative cash flow, $100k terminal value → IRR ≈ negative (small loss)
    - All negative cash flows, no terminal value → None

    **2. Cap Rate**
    - Signature: `calculate_cap_rate(annual_noi: Decimal, property_value: Decimal) -> Decimal`
    - Formula: annual_noi / property_value
    - Returns as decimal (e.g., 0.065 for 6.5%)
    - Edge case: zero property value → return Decimal("0")
    - Quantize to 4 decimal places (0.0001 precision for percentage display)

    Cases:
    - $30,000 NOI / $500,000 value → 0.0600
    - $0 NOI / $500,000 value → 0.0000
    - $30,000 NOI / $0 value → 0.0000

    **3. Cash-on-Cash Return**
    - Signature: `calculate_cash_on_cash(annual_net_cashflow: Decimal, down_payment: Decimal) -> Decimal`
    - Formula: annual_net_cashflow / down_payment
    - Returns as decimal (e.g., 0.08 for 8%)
    - Per user decision: based on initial down payment only
    - Edge case: zero down payment → return Decimal("0")
    - Quantize to 4 decimal places

    Cases:
    - $8,000 annual cash flow / $100,000 down payment → 0.0800
    - -$2,000 annual cash flow / $100,000 down payment → -0.0200
    - $8,000 / $0 → 0.0000

    **4. Equity Position**
    - Signature: `calculate_equity_position(current_property_value: Decimal, remaining_balance: Decimal) -> Decimal`
    - Formula: current_property_value - remaining_balance
    - Simple but important: uses current estimated value (user input), NOT purchase price

    Cases:
    - $550,000 value - $350,000 balance → $200,000
    - $500,000 value - $0 balance → $500,000 (paid off)

    **5. Annual Metrics Summary**
    - Signature: `calculate_annual_metrics(annual_summary: AnnualOperatingSummary, property_value: Decimal, remaining_balance: Decimal, down_payment: Decimal, is_partial_year: bool, months_in_year: int) -> AnnualMetrics`
    - Returns an `AnnualMetrics` dataclass containing: year, cap_rate, cash_on_cash, equity_position, is_partial_year
    - For partial years: annualize by scaling — annual_noi = (noi_so_far / months_in_year) * 12, same for cash flow
    - This is the per-year row enhancement for the P&L table

    Cases:
    - Full year (12 months): use totals as-is for cap rate and cash-on-cash
    - Partial year (6 months): annualize NOI and cash flow before computing metrics, flag is_partial_year=True
  </behavior>
